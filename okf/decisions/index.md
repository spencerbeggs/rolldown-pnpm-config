# Decision

* ["lock" pins to the version verbatim](lock-pins-version-verbatim.md) - derivePeerRange's "lock" strategy reuses the range's version text verbatim instead of rebuilding it from parsed major.minor.patch, fixing a bug where reconstruction silently dropped prerelease/build identifiers.
* [--dry-run replaces --preview on export](dry-run-replaces-export-preview.md) - export --preview conflated write-vs-show; the split is a static export --dry-run and a standalone interactive preview command with a non-TTY fallback.
* [--yes is strict, interactive is lenient](yes-is-strict-interactive-is-lenient.md) - Every planned edit is validated against the registry before rewrite; interactively a rejection is dropped at whole-package granularity and reported, while --yes fails hard on any warning.
* [Builds never write](builds-never-write.md) - The build reads a plugin author's config exactly as authored; only the upgrade CLI rewrites it. A memoized freeze-path sync that violated this was deleted after dogfood adoption exposed both an ungated write and a split-brain correctness defect.
* [Data-driven refines, not injected code](data-driven-refines.md) - Repo-dependent merge behavior is modeled as a data-driven refine on a descriptor, not as arbitrary injected code, keeping the manifest plain serializable data.
* [Default override preservation](default-override-preservation.md) - Every export run preserves file:/link:/workspace:/portal: override entries by default, making the safe behavior opt-out rather than opt-in.
* [Descriptor table as the single source of truth](descriptor-table-as-source-of-truth.md) - One declarative entry per managed pnpm field; deriveSchemas and deriveRegistry produce what code consumes, kept honest by a satisfies-based drift guard.
* [Detection separated from response](detection-separated-from-response.md) - A strategy only detects and classifies divergences; the response (warn/error/silent) lives entirely in applyEnforcement.
* [Effect at build time only](effect-at-build-time-only.md) - Effect is fenced entirely to the build step; the shipped pnpmfile carries zero Effect.
* [Effect v4 collapses the declared peer closure](effect-v4-peer-closure-removed.md) - The v3-era satellite peer-closure workaround in package/package.json is obsolete under Effect v4 and was removed.
* [Interop strategy reconciles the group, not one package](interop-group-reconcile.md) - The "interop" peer strategy reconciles a whole catalog group against its members' cross-peers, pinning at each member's ceiling and downgrading only dependents; the interactive and --yes paths diverge on how conflicts surface.
* [Major bumps are interactive-only](major-bumps-interactive-only.md) - --yes resolves within range only; there is deliberately no flag that applies a major version bump automatically, with one exception for workspace-sourced entries.
* [No execution of the config](static-config-discovery.md) - Discovery and rewrite in the upgrade CLI are 100% static through oxc byte spans; the config is never executed to learn its catalog versions.
* [Shared StyledLine render layer, not per-command ad hoc color](shared-styled-line-render-layer.md) - One StyledLine → toAnsi → ANSI path is shared by export --dry-run, preview and the upgrade summary, with capability detection centralized and threaded in as flags.
* [Standard plugin, no bundler coupling](standard-rolldown-plugin.md) - PnpmConfigPlugin ships as a standard tsdown/rolldown plugin so the library never hard-depends on the Savvy bundler.
* [Surgical span rewrite, operator preserved](surgical-span-rewrite.md) - The upgrade CLI rewrites only the version digits inside a range literal, reuses the existing operator, and applies edits right-to-left so byte spans stay valid.
* [Vendored v4 source as the API authority](vendored-effect-v4-source.md) - Effect v4 source is vendored read-only under .repos/, pinned to the version catalog:effect resolves, and consulted instead of the lagging published docs.
* [local is post-freeze, export-time only](local-is-export-time-only.md) - Per-repo local adjustments belong only in the export step and never in freeze, base, or the bundled runtime artifact, since the pnpmfile must be identical for every consumer of the plugin.
